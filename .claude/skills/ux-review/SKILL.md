# UX-разбор

Метод: `knowledge/methods/ux-heuristics.md`.

1. **Скриншоты.** Свои — пользователь кладёт в `inputs/ux/`. Открытые сайты (свой продукт, конкуренты) снимай сам через
   Playwright MCP: `browser_navigate` → `browser_take_screenshot` с `filename: "projects/<slug>/inputs/ux/NN_<сайт>_<экран>.png"`
   (явный путь обязателен) и `fullPage: true` для лендингов. Мобильный вид: `browser_resize` 390×844.
   Для текста и структуры страницы — `browser_snapshot` (дешевле скриншота). Только публичные страницы:
   не логинься, не вводи данные, не нажимай «Купить/Подписаться». Регистрируй: `./strateg source add --kind image --path <файл> --url <адрес>`.
2. Для объёма вызови субагента `ux-analyst`: путь, экраны, вопрос исследования.
3. Правило привязки: каждое наблюдение указывает экран и элемент («экран 03, кнопка "Подключить" ниже первого экрана»).
   Наблюдение (что видно) → `fact` с источником-скриншотом; интерпретация (почему мешает) → `hypothesis`.
4. Итог: карта пути (шаги → трение → гипотеза → как проверить) и топ-5 проблем по влиянию на целевую метрику.
5. Не придумывай то, чего не видно (поведение после клика, тексты на других экранах) — это `gap`.
