# Этап 4. Варианты и возражения

Метод: `knowledge/methods/options-and-objections.md`. Шаблон: `knowledge/templates/03_options.md`.

## Шаги
1. **Сгенерируй 5–7 кандидатов**, затем сожми до 3–5 **содержательно разных** — различаются ставкой
   (на какую аудиторию / какую ценность / какую модель денег), а не масштабом одного и того же.
   Обязательны: **«Оставить как есть»** (базовая линия: что будет, если ничего не делать, — прогноз) и
   **«Закрыть / свернуть направление»** (что высвобождается, что теряем).
2. **Для каждого варианта** (одна таблица + короткий текст):
   - суть ставки и для кого; что должно быть правдой, чтобы он сработал (ключевые предположения → `assumption`/`hypothesis`);
   - ожидаемый эффект на целевую метрику — **прогноз** с диапазоном и основаниями [P-id];
   - затраты и доходы: порядок величин, допущения [A-id] (`knowledge/methods/unit-economics.md`);
   - риски и нежелательные последствия;
   - первый дешёвый шаг проверки.
3. **Сильные возражения:** вызови субагента `devils-advocate` с описанием вариантов и ссылками на реестр.
   Нужны возражения, которые реально могут убить вариант (не «может быть дорого»). Минимум 2 на вариант.
   Для каждого — ответ или признание: «возражение не снято, риск принимаем/проверяем так-то».
4. **Сравнение** по критериям из брифа (таблица: вариант × критерий; в ячейках — оценка + id оснований).
   Если доступен Jev (`python3 scripts/tools/jev_score.py`) — используй его для независимой оценки вариантов
   по критериям; иначе оценивай сам и отметь, что оценка экспертная.
5. Запиши `outputs/03_options.md`. Факты, гипотезы и прогнозы в тексте помечены id.
6. **Развилка:** предложи свою рекомендацию с обоснованием и спроси пользователя, какой вариант (или комбинацию)
   прорабатывать в стратегию. Запиши `strateg human`. Заведи `recommendation` с `--depends`.
7. `strateg check` → `strateg stage options done`.
