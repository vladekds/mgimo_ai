# Интервью и модельные респонденты

Метод: `knowledge/methods/interviews.md`.

## A. Гайд для реального интервью
Цель → кого ищем (критерии отбора) → разогрев → прошлое поведение («расскажите, когда в последний раз…»), а не мнения о будущем →
альтернативы → барьеры → проверка гипотез без подсказок → завершение. 8–12 вопросов, без наводящих. Сохрани в `interviews/guide.md`.
Напомни пользователю: согласие собеседника, без ФИО и контактов в файлах.

## B. Разбор реальных интервью
1. Расшифровки → `interviews/real/R-01.md` (обезличено). Источник: `strateg source add --kind interview --reliability B`.
2. Кодирование: для каждого фрагмента — тема (боль / задача / альтернатива / барьер / триггер / цитата для коммуникации).
3. Синтез: темы × респонденты (сколько из N упомянули). При N < 10 не выражай в процентах распространённости.
4. Факты вида «3 из 5 респондентов назвали X» → `fact` со ссылкой на источник; обобщения на рынок → `hypothesis`.

## C. Модельные респонденты (синтетика)
Зачем: быстро найти гипотезы, возражения и формулировки ДО реальных интервью; проверить понятность сообщения.
1. Опиши 3–5 персон из данных исследования (сегмент, ситуация, альтернатива, отношение) — с id оснований.
   Добавь хотя бы одну «неудобную» персону (скептик, ушедший клиент).
2. Для каждой вызови субагента `synthetic-respondent` (модель haiku — дёшево) с персоной и гайдом.
3. Сохрани расшифровку `interviews/synthetic/Y-<персона>.md`, зарегистрируй `strateg source add --kind synthetic --reliability E`.
4. Находки → только `synthetic` (или новые `hypothesis` с пометкой «найдено в синтетике, проверить на людях»).
5. В отчёте раздел синтетики всегда с плашкой: «Синтетические ответы не доказывают спрос и распространённость потребности».
